# 填写 PDF 表单

填表单是 PDF 里最容易做错的一件事，因为**存在两种完全不同的表单**，走错路的症状是「值写进去了但看不见」或者「字压到了框线上」。所以流程是固定的，别跳步。

## 第 1 步：判断是哪种表单

```bash
python3 <技能目录>/scripts/check_pdf_form.py input.pdf
```

结果三种之一：

| 结果 | 含义 | 走哪条路 |
| --- | --- | --- |
| `fillable` | 有 AcroForm 字段对象 | 按字段名填，版式不动（第 2 步） |
| `flat` | 没有字段，只有画出来的线 | 按坐标叠加文字（第 3 步） |
| 没有可填字段、也没有线 | 大概不是表单 | 问用户想做什么 |

**为什么不能只看「看起来像表单」**：扁平表单在屏幕上和可填表单长得一样，区别只在 PDF 内部有没有字段对象。判断错了后面全错。

## 第 2 步：可填字段（AcroForm）

### 先列出字段名

```bash
python3 <技能目录>/scripts/list_pdf_fields.py input.pdf
```

输出里最重要的是**字段名**，它是程序用的标识，通常**不是**界面上看到的标签：

```
topmostSubform[0].Page1[0].name[0]
    类型: 文本
topmostSubform[0].Page1[0].agree[0]
    类型: 按钮/复选框/单选
    可选状态: Yes
plan
    类型: 下拉/列表
    选项: Basic, Pro, Enterprise
```

别凭标签猜字段名（界面上写「姓名」，字段名可能是那一长串）。字段名写错时 pypdf 会静默忽略，所以脚本会主动拦下来并列出可用的字段。

### 写 values.json 并填

```json
{
  "topmostSubform[0].Page1[0].name[0]": "Zhang San",
  "topmostSubform[0].Page1[0].agree[0]": true,
  "plan": "Pro"
}
```

值的类型按字段类型给：

- **文本**：字符串。
- **复选框**：`true` / `false`。脚本会问字段自己「开状态叫什么」，通常是 `/Yes`，但不总是。
- **单选组**：给选项名（`list_pdf_fields.py` 列出的「可选状态」里的一个），不是布尔。同一个组里的多个选项共用字段名，所以单选组只能填一个值。
- **下拉**：给选项文本，必须和 `/Opt` 里的一项完全一致。

```bash
python3 <技能目录>/scripts/fill_pdf_form.py input.pdf values.json output.pdf
```

### 填完一定要看一眼

**值存进去了 ≠ 显示出来了。** PDF 的字段值（`/V`）和它显示出来的样子（外观流 `/AP`）是两回事：有些文件由阅读器在打开时渲染，命令行里看到的是空白。

```bash
pdftoppm -png -r 150 output.pdf check      # 或者用 pypdfium2
```

渲染出来确认文字确实出现在框里。脚本会设 `NeedAppearances`，但这不是所有阅读器都认。

### 中文写不进去

如果原表单用的是 Helvetica / Times 这类**内置字体**（编码是 WinAnsi），它只有拉丁字形——中文会变成乱码或空白。pypdf 会打印一条 `contains characters not supported by font encoding` 的警告，脚本也会提醒你。

三条出路，按推荐顺序：

1. **改用坐标叠加**（第 3 步）：`add_pdf_text.py` 用的是 ReportLab 的中文 CID 字体，能正常画中文。
2. **换掉字段字体**：把表单字段的 `/DA`（默认外观）指向一个嵌入了中文的字体。需要手动改 PDF 对象，只在字段很多、坐标叠加不现实时值得做。
3. **接受拉丁化**：如果只是填英文名和数字，本来就没问题。

## 第 3 步：扁平表单（坐标叠加）

页面上只有画出来的线，所以必须自己算位置。

### 先定坐标

坐标单位是**点**（1 点 = 1/72 英寸），**原点在页面左下角**，y 越大越靠上。

把页面渲染成图片，在图上量出像素位置再换算：

```
点 = 像素 × 72 / dpi
```

注意 **图片的 y 从顶部往下，PDF 的 y 从底部往上**，所以要翻转：

```
pdf_y = 页面高度(点) − 图片y(像素) × 72 / dpi
```

举例：200 DPI 的图上量到 (400, 300)，页面是 A4（595 × 842 点）：

- `x = 400 × 72 / 200 = 144`
- `y = 842 − 300 × 72 / 200 = 842 − 108 = 734`

### 先 dry-run 确认落点

```bash
python3 <技能目录>/scripts/add_pdf_text.py input.pdf output.pdf "144,734,张三" --dry-run
```

它会打印页面尺寸并标出每个坐标是否在页面内。**超出页面的坐标会被标 ✗**——那通常意味着 y 忘了翻转。

### 再真正写入

```bash
python3 <技能目录>/scripts/add_pdf_text.py input.pdf output.pdf \
  "144,734,张三" \
  "144,700,2026-01-01"
```

写中文默认用 ReportLab 内置的 `STSong-Light`，不需要字体文件。要用指定字体（比如和表单本身更接近的思源黑体）就加 `--font /path/to/font.ttf`。

### 交出去之前渲染检查

这一步不能省。坐标算错的表现是文字压在线框上、串到相邻字段里，或者跑出页面——只报一个文件名用户是看不出来的。渲染成图片贴给用户看，比说「已完成」有用得多。

- [ ] 中文值确认过字体支持（不支持就改用坐标叠加）
