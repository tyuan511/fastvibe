### Improved

- Editing or retrying a prompt now preserves its pasted text, skill instructions, file attachments, and image metadata. Attachment chips remain editable, and an image-only prompt can be sent without adding a caption.
- Large and long-running conversations now update the chat view with much less repeated work. Settled rows keep their identity while only the streaming tail is rebuilt, which reduces renderer CPU and garbage collection during live replies.

### Performance

- Checkpoints write only newly discovered files during a turn instead of repeatedly rewriting the complete file set.
- Event delivery avoids duplicate payload cloning and repeated scope scans, while client batch-size accounting is cached.
- Large JSONL transcripts use streaming reads, and append-only updates parse only the new byte range.
- Live Markdown blocks avoid reparsing large in-flight blocks on every stream flush. Code highlighting and tool argument updates discard stale intermediate snapshots while preserving the final result.
- The release ships the benchmark suite these numbers come from, so a future version can be compared against it the same way.

### Measured before and after

Each row runs the same code path on v0.22.10 and on this release, with the suite in `scripts/bench-performance.mjs` on one machine: Apple M4, 10 cores, macOS, Node.js 24.19, median of 7 rounds.

| Scenario | v0.22.10 | v0.23.0 | Change |
| --- | ---: | ---: | ---: |
| Checkpoint capture, 32 files added one by one | 5,524 ms | 1.7 ms | −99.97% |
| Event bus, 10,000 events in one scope | 62.1 ms | 14.5 ms | −76.6% |
| Event bus, 10,000 events across 512 scopes | 203.1 ms | 14.5 ms | −92.9% |
| Event bus, 5,000 events carrying 4 KB payloads | 28.2 ms | 17.0 ms | −39.9% |
| Chat rows, 300 turns × 120 stream flushes | 8.86 ms | 1.00 ms | −88.7% |
| Live Markdown, 48 KB block × 150 flushes | 3,159 ms | 797 ms | −74.8% |
| Syntax highlighting, 64 queued snapshots (CPU) | 72.2 ms | 55.0 ms | −23.8% |

These are in-process timings of the work a long conversation repeats, not end-to-end latency: a short chat will not feel different, while a 300-turn chat repainting on every streamed token, or a reply that grows past 48 KB, is where the difference lands. Wall time unless a row says CPU. Memory moved with it — the 48 KB live Markdown run went from about 58 MB to about 2 MB of RSS — and a 4,000-turn, roughly 9 MB transcript opens cold in about 16 ms, with its first page projected in 0.03 ms. Per-round samples, p95 and memory trends are in the benchmark artifacts in the repository.

### Fixed

- Prompt reconstruction now uses the same metadata and attachment ordering across the desktop, transcript reloads, and remote clients, preventing edited turns from silently losing pasted content or attachments.
