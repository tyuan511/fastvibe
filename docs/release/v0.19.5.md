### Added

- **Images, videos and HTML pages a reply makes now show up in the conversation.** Instead of a path you have to open by hand, a reply names each one inline — a Markdown image by path, a file the agent wrote, a picture an MCP tool returned, a path a script printed, or whatever the agent passes to the new `present` tool. When a run finishes and folds, up to three thumbnails sit at the end of its "took …" row, with a "More" button past three. Clicking either opens a full-window viewer that steps through the same batch with ← / → and plays video. HTML pages run in a sandboxed frame: scripts and https libraries work, but a page cannot read your files or reach FastVibe.

### Improved

- **Previewing a large image or video no longer loads the whole file at once.** The file is streamed to the preview instead of being packed into a single message, so photos and movies open quickly and a video can be dragged to any point. Files on an SSH host stream the same way.
- **Changed-file chips have a context menu.** Right-click a chip to preview the file as it is now, reveal it in the folder, or copy its full path. Clicking a chip still opens that turn's diff.
- **A handoff's new chat knows where it came from.** The prompt now ends with the source chat's ID, so the agent can search the earlier conversation with `conversation_search` instead of guessing.

### Fixed

- **A chat interrupted in the middle of a tool call can be resumed.** If FastVibe quit while a command or file write was running, the chat ended on a tool request with no result, so there was no Continue button and the model never learned the call may have half-run. Opening the chat now closes each unanswered call with an error result that says so, and Continue appears.
- **Send now no longer shows your message twice.** When the previous reply was stopped to send a queued message, the message could briefly appear twice in the chat.
