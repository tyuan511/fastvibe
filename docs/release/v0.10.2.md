### Added

- **A remote host's first connection now reports its transfers.** When the Agent runtime or Node.js is fetched, a progress bar appears in the Add project dialog with the phase, the bytes, the current speed and a percentage, alongside the host's own output. It covers every way a deploy gets its files — the host downloading the Agent runtime, the host downloading Node.js, this desktop downloading the runtime when the host could not, and the upload over SSH — and it greys out between steps instead of claiming a transfer that is no longer running.
- **A host behind a proxy can now reach the download.** `ssh host command` never reads `.bashrc`/`.zshrc`, so a proxy configured there — or a Node manager's PATH — was invisible to the deploy scripts, which then failed to reach GitHub or nodejs.org even though the machine itself could. The connect now loads the user's interactive login environment first, with a ten-second budget and a background probe so an rc file that waits for input cannot hang it, and that environment is inherited by the Agent the host starts. Proxy variables are mirrored between upper and lower case, because `curl` and `wget` do not read the same ones, and the one in use is logged with its credentials masked.

### Improved

- **The official source is tried first, a mirror second.** A host that cannot reach GitHub or nodejs.org, or that reaches them too slowly, now falls back to `gh-proxy.com` for the Agent runtime and to npmmirror's copy of nodejs.org for Node.js. The first attempt keeps a short fuse — no connection, an HTTP error, or a transfer stuck below 10 KB/s for 20 seconds — so a blocked host gets to the mirror in seconds rather than after a string of retries.
- **The packaged Agent runtime installs only what the Agent imports.** The archive used to carry the desktop's whole dependency set, including Electron-only packages (the updater, the computer-use driver, icon themes, toasts) that never run on a remote host. The list is now derived from the built module graph, so a new import adds its package by itself. The web client is not shipped with it either: the remote Agent listens on loopback only, on a port the OS picked, so no browser could load that page there.
- **The agent asks before it changes your workspace.** Creating or binding a worktree now comes with instructions to explain why and where, end the reply, and wait for approval — a new checkout is a change to the machine that nobody asked for.

### Fixed

- **Login profiles written for Bash are no longer evaluated by `dash`.** The remote scripts started as `sh -lc`, which already runs `.profile` under `dash` — so switching shells inside the script was too late for a profile containing Bash-only syntax such as `source`. They now select Bash before loading anything, and fall back to `sh` on a host that has none.
- **A slow first deploy no longer fails on the clock.** The bootstrap that may have to download Node.js and start the Agent was capped at 180 seconds; it now has 15 minutes, which a first connection over a slow link needs.
- **Node.js is verified against the checksums of the source that served it.** When the archive comes from the mirror, `SHASUMS256.txt` is read from the mirror too (falling back to nodejs.org), instead of demanding a copy from a host that was just unreachable. The archive is still checked before anything is unpacked, so a truncated download or a proxy's error page can never become the Agent's runtime.
- **The build starts the staged Agent before it is archived.** The packages and files the packaging removes are pruned on the claim that no Agent code path loads them; a smoke test now boots the staged Agent and waits for it to listen, so a wrong entry fails the build with its log rather than a user's connection.
