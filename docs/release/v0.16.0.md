### Breaking changes

- **The permission system and plan mode are gone.** The three permission modes (Ask first, Smart, Full access), the **Always allow** list, the Full access warning, the decision engine's approval judge, and `/plan` with its review panel have been removed, along with every setting and control that belonged to them. A tool now runs as soon as the model calls it. What can still stop a run is a question: the agent's `question` tool, a plugin's dialog, and macOS's own folder-access prompts. Nothing needs migrating — saved permission settings are simply ignored.
- **Azure providers need to be added again.** The built-in Azure provider's id changed from `azure-openai-responses` to `azure` in the pi SDK, so a provider you had configured under the old id no longer appears. Add it again under **Settings → Models & defaults**; its model list and key are not carried over.

### Added

- **Code mode.** The model can write one short script that calls several tools — in parallel, if it likes — and get back only what the script prints, instead of spending a round trip and a transcript row on every call. The transcript shows it as a single **Script** card: the script itself, each tool it ran with its status and timing as it goes, and the output. Turn it off under **Settings → Preferences → Chat → Code mode**; it is on by default.
- **Tool search.** The model can look up tools that were not handed to it up front and load the ones it needs, which keeps a long MCP tool list out of every request. On by default; **Settings → Preferences → Chat → Tool search**.
- **Choose how each MCP server's tools are offered.** In a server's form, **How tools are provided** is **Directly** (every tool is given to the model, as before), **On demand** (found through tool search) or **Only from scripts** (callable from code mode only). A server set to either of the last two keeps the matching tool on even if its switch is off.
- **Edit MCP servers as JSON, and edit the ones you have.** The MCP server dialog has a **Form** and a **JSON** view. Paste the `mcpServers` config from a server's README (Claude Desktop, Claude Code, Cursor and VS Code layouts all work, and so does a fragment without its outer braces); a server with the same name is replaced and keeps its tools' names. Servers can now be edited after adding, with **Environment variables** for local servers and **Request headers** for HTTP servers — enough to use a bearer token.
- **The agent can ask you questions in any chat.** The `question` tool, which only existed inside plan mode, is now always available.

### Improved

- MCP tool results keep their images, and a result the server marks as an error is reported to the model as one. Pressing **Stop** now cancels a tool call that is waiting on a server.
- A local MCP server starts with a short, fixed environment plus the variables you set, instead of everything FastVibe itself runs with. A server that exits while a chat is open now shows as disconnected rather than still connected.
- HTTP servers written as `{ "url": … }` in a pasted or hand-written `mcpServers` config are no longer dropped.
- Upgraded the pi SDK to 1.0.4.
