### 改进

- 编辑或重试提示词时，现在会保留粘贴文本、技能指令、文件附件和图片元数据。附件卡片仍可单独编辑；只有图片、没有文字说明的提示词也可以直接发送。
- 大型和长时间运行的会话现在会减少重复的聊天视图计算。已经完成的消息行会复用原有对象，只重建正在输出的尾部，从而降低流式回复期间的 renderer CPU 和垃圾回收压力。

### 性能

- 同一轮中，checkpoint 只写入新发现的文件，不再随着文件列表增长反复重写完整文件集合。
- 事件分发减少重复 payload clone 和重复 scope 扫描，客户端 batch 大小计算也会缓存。
- 大型 JSONL 转写使用流式读取；只追加内容时只解析新增的 byte range。
- 流式 Markdown 对较大的正在生成内容降低重复解析频率。代码高亮和工具参数更新会丢弃过期的中间 snapshot，同时保留最终结果。
- 版本中自带这批数字所用的基准套件，后续版本可以用同样的方式与本版本对比。

### 升级前后对比

每一行都是同一段代码在 v0.22.10 与本版本上的实测结果，使用版本自带的 `scripts/bench-performance.mjs`，同一台机器：Apple M4，10 核，macOS，Node.js 24.19，取 7 轮中位数。

| 场景 | v0.22.10 | v0.23.0 | 变化 |
| --- | ---: | ---: | ---: |
| checkpoint 捕获，32 个文件逐个加入 | 5,524 ms | 1.7 ms | −99.97% |
| 事件总线，单 scope 内 10,000 个事件 | 62.1 ms | 14.5 ms | −76.6% |
| 事件总线，512 个 scope 共 10,000 个事件 | 203.1 ms | 14.5 ms | −92.9% |
| 事件总线，5,000 个事件、每个 4 KB payload | 28.2 ms | 17.0 ms | −39.9% |
| 聊天行重建，300 turn × 120 次流式刷新 | 8.86 ms | 1.00 ms | −88.7% |
| 流式 Markdown，48 KB 内容块 × 150 次刷新 | 3,159 ms | 797 ms | −74.8% |
| 代码高亮，64 个连续 snapshot（CPU） | 72.2 ms | 55.0 ms | −23.8% |

这些是长会话里反复执行的那部分工作在同一进程内的耗时，不是端到端的响应时间：短对话不会有什么感觉；而在 300 turn 的会话里每吐一个字都要重绘、或者一条回复长过 48 KB 时，差别就落在这些地方。除标注 CPU 的行外均为 wall time。内存也一起降下来了——48 KB 流式 Markdown 那一组从约 58 MB RSS 降到约 2 MB——4,000 turn、约 9 MB 的转写冷打开约 16 ms，首页 projection 0.03 ms。每轮样本、p95 和内存趋势保留在仓库的基准产物里。

### 修复

- 提示词重建现在在桌面端、转写重载和远程客户端之间使用相同的元数据与附件顺序，避免编辑后的 turn 静默丢失粘贴内容或附件。
