### Added

- **Conversations archive themselves once they go stale.** A chat nothing has touched for 30 days moves to Settings → Archived chats on its own, and Restore puts it back in the sidebar. The window is yours to set there (Auto archive: 30 days by default, Never to switch it off). Chats you are still using are never taken: side chats, empty drafts, a chat that is running, the chat you have open, and anything you pinned — a pin means "keep this where I can see it". A batch says so once, with the same Undo the manual archive offers.

### Improved

- **Windows and Linux get a title bar of FastVibe's own.** One 40px row across the window now holds the logo, back/forward and the window controls, instead of a native bar stacked above an app that already had a top row. The controls keep their system metrics (46px wide, flush to the corner, close in its own colour), and Collapse sidebar and Search moved into the sidebar's top row, next to the panel they act on.
- **Computer control recovers by itself.** The driver ends an idle session after five minutes and FastVibe never restarted it, so the first screenshot or click after a break failed with "the session has ended" and every later computer action stayed broken until you restarted the app — which looked like "everything works except computer control". A call refused for that reason now revives the session and tries once more, and a real tool error is still reported as it is rather than retried.
- **A task-graph node that reuses a configured subagent runs with that agent's tools.** An agent with no tool list of its own means "unrestricted" — that is how the built-in worker is defined — and a node reusing it was silently downgraded to the read-only set. That also made the scheduler believe the node wrote no files, so two nodes editing one directory could run at the same time.
- **Linux on ARM is installable.** The release builds an arm64 AppImage and `.deb` alongside the x64 ones.

### Fixed

- **A model that starts repeating itself is stopped instead of left running.** A degenerate reply writes the same block over and over and never ends on its own: one real reply streamed 376 KB of the same 406 characters for 27 minutes before it was stopped by hand. FastVibe now watches the reply as it streams and ends the run once the same block has repeated eight times, leaving a note in the transcript that says why. The reply's text and the model's thinking are both watched; a tool call's arguments are not, so a generated file is never cut in half. Messages you queued keep running, and a reply FastVibe stopped on purpose gets neither a "task complete" nor a "task failed" notification.
- **Clicking a "task complete" notification opens the conversation again.** The notice could be released before you clicked it, which made macOS bring the app forward while the jump to the chat never happened.
- **The queued-message tray no longer shows through the input.** The follow-up queue slides under the input card so the two read as one shape, and the card's solid fill used to hide that part. With the glass effect on the card hides nothing, so the tray's fill doubled up into a lighter band across the top of the input with the tray's bottom edge drawn through the placeholder. The tray is now cut to the card's outline instead.
- **A pinned prompt no longer lets its reply show through.** With the glass effect on, the rows behind a pinned prompt are cut off at the prompt's lower edge. That cut stopped one frame too early, and the rows the prompt stayed parked on once the next turn pushed it off the top edge read as one garbled line through the translucent bubble.
