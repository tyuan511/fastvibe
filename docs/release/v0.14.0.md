### Added

- **Remote access over IPv6 on the local network.** When LAN access is on and the machine has both an IPv4 and an IPv6 address, Settings → Remote access offers an address-family choice, and the server rebinds to it at once. IPv6 addresses are shown and linked in bracket form, and a link-local address carries its interface zone so a browser can actually open it.

### Improved

- **The remote QR code points at the mobile app.** Its hint now says to scan it with the FastVibe mobile app to connect, and the copy / code / open icons next to an address are spaced further apart.

### Fixed

- **Switching chats quickly no longer jumps back to an earlier one.** Opening a conversation loads its session asynchronously, so a slower open, fork or new chat that finished after a newer one could take over the active conversation and pull every window back to it. Only the most recent request may now switch the active chat.
- **A large reply no longer disconnects a remote client.** The send-buffer guard counted the outgoing message itself, so a single long transcript closed the socket even when nothing was queued. It now only looks at the backlog.
- **A reconnecting browser client no longer switches the desktop's chat.** After a dropped connection the web client reopened the chat named in its (possibly stale) URL, which changed the conversation every desktop window was showing. It now follows the engine's active conversation and only falls back to the URL when none is active.
- **The web client works over plain HTTP on the LAN.** Some browsers do not offer `crypto.randomUUID()` outside a secure context, which broke sending messages and attaching files from a client opened at an `http://` LAN address. Ids are now generated with a fallback that works in every browser.
