### Added

- **Remote access now carries images as binary frames.** An attached screenshot is sent as one binary WebSocket frame and referenced by id, instead of being base64'd into the JSON call. The client and the server negotiate the capability in the handshake (`features.binaryAttachments`), so an older client keeps sending the original JSON unchanged. Frames are held per connection for 60 seconds and capped at 32 MB, and an incomplete upload is reported as an error instead of silently arriving without its image.
- **The public address row offers copy, open and QR.** Settings → Remote access now draws the LAN address and the tunnel's public URL the same way: the URL, then copy / code / open as hint-labelled icons. The QR code opens as a popover on hover (click still toggles it) because a tooltip that closes when the pointer moves cannot be scanned, and it is only offered for an address another device can actually reach — a code for a loopback address scans fine and then fails with "connection refused".
- **Companion Android app.** `apps/mobile` is an Expo app that connects to a FastVibe machine over the same remote server: saved hosts, QR-code pairing, the chat list, the transcript with tool cards, model / thinking / permission chips, and approval prompts. It is built by its own workflow and is not bundled with the desktop app.

### Improved

- **Compaction is drawn inside the reply it belongs to.** The "compacting context" card was a transcript row of its own, which split a reply into two blocks and two footers. It is now a part of the assistant message, so it sits where the compaction actually happened and is replaced in place when the summary arrives.
- **The public URL's copy button no longer depends on where the server listens.** Address rows share one component, so the string that is copied, the address the link opens and the data the QR code encodes cannot drift apart.

### Fixed

- **Transcript positioning stays correct when switching and streaming.** The virtualized message list now keys its scroll state by conversation instead of the first message, uses the DOM's actual scroll height after measurement, settles the position again after the next layout frame, and keeps following new streamed text without mistaking a transient layout gap for a reader scroll. This fixes restored or forked chats opening partway up the history, including the desktop side chat and the mobile screen.
- **A native provider's edited models survive an SDK upgrade.** Tuning a built-in provider's model (name, context window, max output, reasoning, input modalities, thinking levels) used to be discarded: native providers were never written to the engine configuration, so the detail dialog was read-only. The edits are now persisted as a `modelOverrides` block while the provider's identity, endpoint and protocol stay owned by the SDK, and unedited rows are refreshed from the catalog as before.
- **A compaction's system prompt no longer shows up in the transcript.** The SDK keeps the active system prompt on a compaction entry so the model can rebuild its context; projecting it put a stray notice between the reply and the compaction card.
- **A slow remote client is disconnected instead of buffering without limit.** A phone on a weak link could grow the server's send buffer until the process was holding hundreds of megabytes. Sends now measure the socket's buffered amount and close the connection past 2 MB. WebSocket compression is also enabled at a low level, which lowers the cost of streaming a long reply over a tunnel.
- **Message timestamps are localised.** A reply's footer time was formatted with the runtime's locale rather than the interface language, and an older reply could be stamped with a time from a different day without saying so.
