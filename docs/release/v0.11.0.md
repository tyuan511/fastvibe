### Added

- **The decision engine can drive the browser and the desktop.** Settings → Decision engine is Off or Jev. A Jev API key is checked before it is stored. Under Scenarios, Browser control and Computer control hand clicks and typing to Jev one step at a time (`browser_task` / `computer_task`); opening a page, snapshots, screenshots, and menus stay with the main model. A task row shows the goal and a Jev badge with the step count and time. Turning a scenario off takes effect on the next turn.
- **Batch decisions and approval judging.** With batch decide on, the main agent can score or choose across many items in one call. "Approve for me" can ask the decision model instead of the main model.
- **Browser use can drive a real Chrome window.** Settings can launch a dedicated system browser over CDP, instead of only the side-pane page. The side pane also gains viewport size, zoom, find, element picking, and cookie import.
- **A phone page and a self-hosted tunnel.** Phones get their own page: chats ordered by waiting on you, running, then recent, with the same transcript and approval panel. Reading one there no longer switches the chat on the desktop. Remote access can open an frp tunnel to your own frps; HTTP mode checks that the domain points at the server and names the port to open when the first login times out.
- **One proxy for the app.** Settings can send model calls, logins, updates, downloads, and the built-in browser through the system proxy or a custom HTTP(S) proxy.
- **The phone layout keeps up.** The sidebar drawer closes after you pick something, touch targets stay visible, and scrolling no longer reorders chats. Settings and Providers are a list, then a page. Enter inserts a newline. Codex and Claude join the theme list, each in light and dark.
- **Layout is remembered.** Side-pane width, which folders are open in the file tree, and which projects are folded in the sidebar survive a restart.

### Improved

- **Search shows why a chat matched.** The command palette marks the query in the title and in an excerpt around the hit, instead of a short grey hint.
- **A browser task waits for the page to settle.** After a click, the loop reads until the new page has held still, so a mid-transition page is not clicked twice. If the page never holds still, the run stops instead of deciding forever. Pagers and nearby off-screen controls can be used, and date and time fields can be filled.

### Fixed

- **A queued follow-up no longer sticks on "Sending…" after a chat is reopened.** The queue adapter is installed again for the new session.
- **Passwords stay out of page snapshots.** A password field is no longer sent to the model as its current value, and stale element marks from an earlier snapshot are cleared.
